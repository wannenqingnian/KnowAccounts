# 0.13.0 基础MVP补齐

## 报销

支出表单开启“标记待报销”。管理→报销管理，或点击原支出→记录报销到账，填写实际到账金额、到账账户及日期。每笔可多次到账；状态根据未删除的关联记录实时计算为待报销、部分报销、已报销；全部由退款结清的显示已结清。

报销在数据库中使用关联退款分录加 `is_reimbursement=1` 区分，界面明确显示报销到账。它增加到账账户余额，但不计普通收入；消费净额=支出−到账退款−报销到账，预算使用相同净额。跨月到账只影响到账月份，不回写原月统计。分类/标签环图仍显示抵扣前的消费结构。待报销仅是标记，不提前冲减现金消费。

报销通知不自动推断对应原支出，包含报销的通知保留待核对，明确报销到账的文本/OCR要求使用报销管理关联，避免误计普通收入。

原消费金额是退款和报销到账的共同上限。禁止关联其他账本、非支出、已删除或未标记报销的交易；修改、删除、恢复到账记录均重算状态和余额。原消费已有有效退款/报销时不能直接改账或删除，先处理关联记录。图片附件可以独立管理。

## 图片附件

记账/编辑表单可添加；点击流水→图片附件，可以单独增删和保存，不重写交易金额。每笔最多5张，每张不超过4 MB，支持PNG/JPEG；原生文件选择后检查文件大小和编码尺寸（最多24 MP、单边不超过10000像素）。缩略图及大图限制解码尺寸，预览支持缩放。

附件存为SQLite中的独立记录（Base64文本），正常流水只加载数量，打开附件时加载内容。新增账目、附件及来源确认在同一事务内保存；取消表单/附件管理不保存修改。账目删除只软删除，附件随回收站恢复；移除图片后在当前数据库中删除记录，已有导出备份不受影响。

全账本AES-GCM密码备份包含附件。继续使用50 MB备份大小上限；图片较多时可能超限，导出明确报错，不生成缺图备份。恢复在临时数据库校验图片格式、大小、数量和交易引用，失败不覆盖当前数据。这里没有加入云存储、拍照、PDF或自动保存OCR截图附件。

## 金额隐私模式

管理→金额隐私模式。隐藏总览、流水、账户、草稿、报销列表中的格式化金额及预算/分类金额条；分析页隐藏金额、比例及全部图表。开关保存在SQLite设置，随重启和加密备份保留。金额解析、分录、后台自动记账及统计数值不变。

这是展示金额开关。主动编辑账目/账户/预算、打开图片、查看备注或OCR原文时仍可能看到金额，界面说明这些边界；它不是数据库加密或系统截屏保护。

## 迁移与验证

Schema v5：交易增加报销区分字段，增加附件表及交易索引。支持v1/v2/v3/v4→v5，以及上述版本加密备份恢复。旧交易默认非报销到账、附件为空。

专项覆盖多次/部分/跨月报销、退款共同上限、编辑/删除/恢复、账本隔离、坏附件事务回滚、附件数量及尺寸、加密备份及坏文件保留原数据、真实v4迁移与v4备份恢复，以及报销/附件/隐私UI交互。通知/无障碍/OCR继续运行已有回归与最终APK入口/JNI校验。

本轮ADB没有可连接设备，也没有可用的KVM模拟器。自动测试和安装包检查不等于Android真机稳定性验收；Android 16/一加后台限制和各支付软件实际页面仍待真机测试，见[AUTOMATION_DEVICE_CHECK.md](AUTOMATION_DEVICE_CHECK.md)。

最终验证：166项Flutter测试全部通过，静态分析无问题，12项原生JUnit测试重新执行通过。ARM64 Release约26.26 MiB（27.5 MB），versionCode 2015，开发签名与0.12.0一致；最终DEX保留12个JNI类及9个构造函数，后台Dart入口、受保护通知/无障碍服务与12个来源包均通过安装包检查，未内置模型。临时下载回读文件与本地APK的SHA-256一致。

# 0.4.0 来源、草稿和待确认箱

## 使用方式

首页“一句话记账”输入描述，点“识别账单”会在本地持久化来源及草稿，但不影响余额、预算和统计。可以立即“核对并记账”，也可以关闭页面，稍后在首页待确认卡片或管理页进入“待确认账单”。取消确认表单会保留原始识别草稿，尚未保存的手动字段修改不会保留。

待确认箱逐笔显示原文、金额、日期和歧义提示。长按可批量确认安全账单、批量忽略，或统一修改账户、分类、标签和目标账本；执行前显示预计变化与跳过原因，失败时整批回滚。重复候选按订单号或多字段证据成组审核。复杂退款、转账、亲情卡、贷款和外币等仍提示使用对应专用入口。忽略后原文保留在本地和备份中，可从“已忽略”恢复或清理。

## 持久化规则

Schema v3 新增 `raw_transactions`：账本、来源类型、原始文本、采集时间；`transaction_drafts`：来源引用、解析器版本、JSON 解析快照、状态、正式交易引用、更新时间。原文中的连续/空格/横线分隔的13位以上数字（含全角）仅保留尾号，避免将完整银行卡号写入来源库；这也会脱敏订单等长编号。此版本未接入平台交易ID去重，后续应新增结构化安全来源标识。

同一输入会话重新识别会更新其待确认草稿。不同会话中的相同描述会生成不同草稿，尚未实现跨来源去重。识别框内编辑但没有再次识别的文本不保存。

待确认箱重新解析原始资料，采用原始采集日期，以及当前有效的账户/分类列表。旧的分类或账户引用不会直接进入表单。JSON 快照保留初次或最近一次显式识别结果供后续审计，不作为正式账目或概率评分。

确认事务同时保存正式交易、账户分录和来源关联。失败则整体回滚；同一草稿重复确认返回已有交易ID，不再写交易/分录。已确认账目被删除后，重新确认不会重新创建它；请从回收站恢复。已确认账目之后可按普通账目编辑，源快照保持原样。

所有操作按账本隔离。支持从 SQLite v1/v2 原地升级到 v3；保留旧账户、交易和信用元数据。密码备份包括新表和正式交易关联。恢复旧 v1/v2 备份时补入空来源/草稿表，备份恢复仍先检查临时数据库、再原子替换。

## 验证边界

测试覆盖持久化重开、相对日期、草稿隔离、更新同一草稿、忽略、失败回滚、重复确认、旧 v2 数据库、真实旧 v1/v2 格式备份、新版本备份关联、大字体及键盘布局、取消后从待确认箱继续记账。界面预览由实际 Flutter 渲染，使用独立演示数据。

0.5.0 已接入按需模型的 Android 本地 OCR，截图文字可核对修改，再走同一草稿流程；之后扩展 iOS、语音、通知、来源去重、规则分类。当前原文 SQLite 未整体加密；加密导出文件包含原文。未进行 Android 真机安装、系统杀进程或原生插件行为验证。

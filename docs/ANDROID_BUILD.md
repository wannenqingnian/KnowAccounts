下载来源为 Google 官方 Android 仓库和 Adoptium。手动下载的 Android 平台、Build Tools、Platform Tools 和 NDK 均按官方仓库清单核对大小及 SHA-1。

云环境的代理及 Java 证书配置保存在工具链目录中。项目源码不包含此环境的代理配置，也不包含 SDK、JDK、Gradle 缓存或签名私钥。

## 在当前工作区重新构建

```bash
cd /workspace/smart_ledger
JAVA_HOME=/workspace/toolchains/jdk-21 \
ANDROID_HOME=/workspace/toolchains/android-sdk \
ANDROID_SDK_ROOT=/workspace/toolchains/android-sdk \
GRADLE_USER_HOME=/workspace/toolchains/gradle-home \
/tmp/flutter-sdk/bin/flutter build apk --release --target-platform android-arm64 --split-per-abi
```

输出目录：`build/app/outputs/flutter-apk/`。当前只生成并交付 `app-arm64-v8a-release.apk`，包含ARM64一种架构。

现代 Android 手机通常使用 arm64-v8a；旧款 32 位 ARM 设备使用 armeabi-v7a；x86_64 用于对应的模拟器或设备。安装时只选一个匹配设备的包。

## 在自己的电脑构建

安装 Flutter、Android Studio/Android SDK 和兼容 JDK 后执行：

```bash
flutter doctor
flutter pub get
flutter build apk --release --target-platform android-arm64 --split-per-abi
```

`android/local.properties` 为本机生成文件，不包含在源码包中。Flutter 会根据本机配置生成其中的 SDK 路径。

## 签名和验证范围

当前 Debug 和 Release APK 均使用 Android Debug 开发签名，适合安装测试。Release 构建已优化代码，但正式发布仍需要配置自己的发布签名并妥善保管密钥。

编译、APK 签名与包信息检查不能替代真机验证。仍需在 Android 设备上检查启动、数据库持久化、备份文件选择器及输入交互。

## 0.9.1 Release JNI闪退修复（仅ARM64）

版本0.9.1+11，版本码2011，APK 27,341,944字节（26.08MiB）；SHA-256：`16b58017682a04736a6fc6f95ad4160210d4f27b5ab65b47d5912f797ea40081`。保持原开发签名，支持覆盖升级，OCR active-v2模型无需重下，账本Schema不变。

用户Android16/ARM64日志显示`convertToTensorInfo`内`GetMethodID`因`java_class == null`触发SIGABRT。确认0.9.0 R8删除`TensorInfo`并改名多个ONNX类型；ONNX Runtime 1.23.2和OpenCV 4.12.0的AAR均没有consumer ProGuard规则。原生OrtJniUtil.c通过固定`ai/onnxruntime/TensorInfo`类名查找`([J[Ljava/lang/String;I)V`构造函数，Java/Kotlin引用分析无法覆盖这种调用。

增加release proguard-rules.pro，完整保留ai.onnxruntime与org.opencv包内类和成员，继续优化App代码。新APK检查12个JNI引用类定义和9个JNI构造函数签名都存在且保持固定名称；旧0.9.0 APK同项检查失败，包含用户栈对应的缺失类。检查直接解析DEX的class_defs与编码方法，不以字符串存在或mapping条目代替类定义。

每次Release构建后执行：

```bash
python3 tool/verify_ocr_jni_apk.py build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
```

单ABI、最低API24、压缩原生库、截图服务/权限、签名与模型不内置检查通过。该检查能验证本次JNI打包原因已消除，尚无连接的手机或模拟器可运行设备端推理。

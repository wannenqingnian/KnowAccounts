# 统一置信度引擎

`0.29.0` 开始，OCR、通知、无障碍、语音和一句话记账草稿使用同一套版本化置信度结构。`0.29.1` 引擎标识为 `confidence-rule-v2`，增加可审计的离线校准与来源隔离。

## 当前输出

每次评估固定输出：

- 来源类型与模型版本；
- 金额、商户、账户、时间、完成状态、分类、收支方向和来源质量八个字段分数；
- 整单分数与 `autoPost`、`review`、`manual` 三档决策；
- 触发降级或拦截的中文理由；
- 实际采用的自动入账、关键字段和人工填写阈值；
- `calibrated` 与校准配置版本。

结果写入草稿 `parsed_json.confidence`，跟随本地数据库与加密备份保存。旧草稿没有该字段时仍可读取，不修改 SQLite Schema。

## 安全策略

- `autoPost`：整单至少 0.90，所有关键字段至少 0.85，无未处理警告，并且是普通收入或支出。
- `review`：字段可以形成草稿，但至少一项未达到自动入账条件。
- `manual`：缺少金额、商户、账户、日期、完成状态等关键证据，或解析器已阻止处理。
- 退款、转账、借贷、亲情卡及字段冲突始终降级，不因总分较高而绕过人工核对。
- OCR 行分只作为文字质量证据，不直接等于账单正确概率；缺少逐行评分时禁止 OCR 自动入账。
- 语音、一句话记账和批量导入当前保留用户确认步骤。

## 离线校准闭环

标注样本使用 JSONL，每行只包含随机样本编号、来源、模型版本、置信度快照、人工判断是否正确以及是否具备自动入账资格。校准工具会拒绝 `text`、`raw`、`merchant`、`amount_minor`、`account_id`、`notification` 和 `ocr_text` 等敏感字段。

运行：

```sh
dart run tool/calibrate_confidence.dart samples.jsonl notification source-profile-v1 notification-2026-10 result.json
```

回放按来源与模型版本隔离，输出自动入账数、正确数、误记数、拦截数、审核率、误记率和 Wilson 95% 上界。同一批样本和参数会得到相同指标。

配置必须同时满足：

- 至少 200 条同来源标注样本；
- 至少 100 条候选自动入账样本；
- 自动入账误记率的 95% 上界不高于 1%；
- 阈值不得低于默认保守门槛：整单 0.90、关键字段 0.85、人工填写 0.55。

通过审核的 profile 放入 `assets/confidence_profiles.json` 后随 APK 签名打包。运行时仍会重新计算安全门槛，并校验来源和模型版本；无效、重复或不匹配的 profile 被忽略。

# 自动记账真机验收清单（0.13.0）

本轮开发环境 `adb devices -l` 无设备，以下验收尚未执行。只能将通知/无障碍识别、重放与保守去重的代码及测试标为已实现。

覆盖安装0.13.0，保留原数据及OCR模型。管理→自动记账配置目标账本、测试软件、默认账户/分类并保存，分别授予通知监听及可选无障碍权限。不要为了测试去删除账本或重置应用数据。

| 场景 | 预期 |
| --- | --- |
| 微信/支付宝各一次新的真实付款通知 | 明确字段完整自动保存，账户按实际付款方式，记录增加一笔 |
| 同笔通知+支付详情页面+截图 | 首笔保存；其余重放跳过或疑似重复进入待确认，不自动多记 |
| 微信普通聊天、验证码、营销消息；其他聊天/主页 | 不形成账单，不保存无关页面正文 |
| 付款待支付、失败、退款、转账、多金额冲突 | 不自动当消费保存，必要时人工处理 |
| 支付方式是掩码银行卡 | 匹配已配置尾号；不确定时待确认，不误记微信零钱 |
| 通知金额清楚但商户/账户不明确 | 待确认并保留警告，不补造字段 |
| 系统无障碍关闭，再开启 | 关闭后不采集页面；恢复后按保存的来源范围采集 |
| 自动记账总开关关闭 | 停止新采集；不删除已记账数据 |
| 后台/锁屏运行30分钟、切换软件、系统回收进程后重新进入 | 队列能恢复，无重复正式交易；记录失败及恢复情况 |
| Android 16一加电池优化开启/关闭 | 分别验证权限、服务重连和后台行为，不承诺绕过系统强制停止 |
| 报销/图片附件操作与自动记账交错 | 无数据库锁错误、附件丢失或交易重复；余额和报销状态准确 |
| 隐私模式开启后后台入账，返回App | 自动保存仍工作，界面金额保持隐藏 |

记录系统版本、App版本、来源软件版本、步骤、结果及错误提示。不要分享完整卡号、聊天或原始通知日志。若连接ADB，可运行 `python3 tool/check_automation_device.py --adb /path/to/adb` 检查版本及授权状态；它不会读取通知正文或页面内容。

通知/无障碍权限已授权，只证明系统设置状态；最终仍须对照真实付款结果及账本记录完成上述验收。

### 0.14.0 弹窗补充验证

- 授予悬浮窗权限并启用“识别后弹窗记账”；未授权仍应有待确认草稿。
- 微信消费、转账成功、发出红包和收到红包：需要可读付款页面，识别后核对账户及收支方向；自己的账户间转账应等额增减两个账户、不计入收入/支出。
- 填写部分字段→收起→拖动悬浮球→展开：字段应保留，键盘不遮挡保存按钮；实际支付软件继续可操作。
- 连续两笔：表单按顺序处理，保存/忽略后下一笔可从悬浮球展开；同一笔重复通知/详情不得重复入账。
- 切换权限页面但不改配置不应取消排队；后台故障/超时应可重试。进程终止后的草稿在待确认箱仍可核对，悬浮窗编辑未承诺跨进程保留。
- 本版本构建环境仍没有授权连接的 Android 真机，以上场景待实际手机验证。


## 导出诊断日志（0.14.1）

管理 → 智能记账 → 日志记录，确认日志开启，右上角清空日志。返回微信重现一次失败的支付/转账/红包，在成功页或账单详情停留片刻；回到日志页，右上角复制完整日志或导出TXT。记录当时采用通知还是无障碍增强，以及是否出现悬浮窗；将日志提供给开发者。日志不自动上传，不包含财务原文，清空不会删除账目或草稿。

0.14.2微信转账卡片回归时，日志应依次出现 `event_text_read`、`matched`和 `queued`，随后出现 `worker_pending`及悬浮窗事件。若仍只有 `node_read`/`money_missing`，表示当前微信版本没有向无障碍提供卡片文本，需转入截图OCR兜底。

0.14.3：先在OCR模型管理确认任一档位可用，再开启“微信转账截图OCR兜底”，并到系统设置关闭后重新开启知账无障碍权限。清空日志后立即发起一笔转账，停留在含新卡片和当前时间的聊天页。成功日志应包含 `screenshot_requested → ocr_started → ocr_matched → queued → worker_pending`。`ocr_model_missing`表示需重新下载模型；`screenshot_unavailable`表示需重新授权或系统禁止截图；`ocr_no_match`表示OCR未同时获得近期时间、金额、动作和卡片标签。

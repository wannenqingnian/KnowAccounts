# Android自动记账（0.14.3）

## 启用

管理 → 自动记账，选目标账本，启用自动记账，按需启用无障碍增强及各软件；更改后自动保存，也可点击“保存设置”。通知权限、无障碍权限须本人在系统设置授予。默认关闭采集，无需OCR模型、银行登录或交易API密钥。

可为每个软件设默认付款账户和默认支出分类。混用多张卡时建议保留“未识别时待确认”。只有确认该软件固定使用某个账户时才绑定；明确的付款字段和账单分类优先于默认设置。来源软件不能代表资金账户：微信支付可使用银行卡、支付宝可使用花呗，京东或美团也不能凭来源推断扣款卡。

通知模式只处理新的交易通知，不回放授权前的整批通知。无障碍只在选中软件里遍历有限的可见文字节点，跳过密码和已知聊天窗口；只有独立成功状态、金额以及至少一个明确交易字段/详情标记时才保存采集，其余页面内容不保存。仅读取文字，不点击、不执行手势、不支付、不截取持续视频，不上传通知或页面内容。没有可读取文字的图片/网页可改用已有截图OCR。

Android13及以上的侧载APK可能提示“受限设置”，需在知账应用信息菜单允许受限设置后授权，应用不会绕过系统限制。受厂商后台管理、强制停止、工作资料/低内存设备限制及第三方UI更新影响，授权后仍需真机验证。开关关闭或撤销权限时停止相关新采集。

## 处理与保存规则

1. NotificationListenerService排除分组摘要、普通聊天（可信支付渠道可带回复动作）、未选软件、营销/验证码、失败、未完成及退款/还款等复杂消息；微信只接受指定支付通知标题。不同通知版本可能因此漏识别，不能把普通聊天当交易。
2. 无障碍观察窗口状态与内容变化，按软件包和支付Activity族路由；事件文本、描述、事件源子树和当前根节点在12秒短会话中去重合并，最多120行/4000字。首次读取约160ms，缺字段在2.2秒内分级重试，不再因连续刷新无限推迟。节点仍不足时才执行一帧本地OCR；只访问用户开启的来源，跳过密码，不点击、不执行手势。
3. 原生队列在应用私有存储保留捕获时的账本/默认绑定与时间；长卡号和订单号只保留尾号。最多100条、48小时，超限/过期丢弃数量在界面显示，防止无限缓存。
4. 短生命周期无界面的FlutterEngine执行保留的Dart入口，打开相同SQLite/WAL数据库。首次初始化、解析和正式分录在本地完成；处理失败不确认队列，保留待重试，不输出财务原文日志。监听服务重连和打开应用可继续处理；失败时可从设置重试。
5. 金额用字段角色区分实付、余额、优惠和订单金额；通知支持明确“向某商户付款”等句式。未知商户不补成软件名，泛指银行卡不自动绑定具体卡；“微信支付/支付宝”等渠道名不等于实际扣款账户，银行卡掩码尾号参与具体卡片匹配；原始歧义保留在待确认警告中。
6. 通知无明确日期时，只对两分钟内处理的新通知采用通知日期；延迟时待确认。无障碍页面没有明确日期始终待确认。外币、转账、借款与还款不自动入账；退款按实际退款金额生成待确认草稿，唯一匹配到同账户、同商户的原消费时自动关联，否则由用户选择原消费后保存。
7. 自动保存需启用该选项，具备正金额、确定的账户/分类/商户/有效日期、明确成功状态且没有警告。弹窗模式优先，不直接自动保存，先持久化草稿供表单确认；关闭弹窗后仅明确交易才可自动保存。否则持久化到“待确认账单”；不计入余额，核对保存后才计入。默认支出分类不用于收入。
8. 采集SHA-256标识生成稳定草稿ID；事务内确认与来源关联。进程中断后重放同一采集不会重复记账；删除已保存交易后也不自动复活。订单号作为稳定标识长期去重；无订单号时把金额/对象限定在一次页面会话内，并在4秒内合并通知、无障碍和OCR的重复报告。新的窗口会话或微信聊天中新追加的转账卡片会生成新标识，因此同对象、同金额的下一笔真实转账不会被永久过滤。
9. 自动保存前在同一SQLite事务检查统一来源证据。通知、无障碍、OCR、语音、CSV/Excel 与手动补账优先按平台隔离的订单号哈希匹配；无订单号时必须同时符合金额、标准化商户、同日时间窗口、账户和方向。金额单独不产生合并候选。冲突金额、商户、时间、账户或方向会显示差异并留待人工决定，不会静默合并两个真实购买。普通流水支持人工“合并为同一笔”和撤销；亲情卡继续使用其专用证据链。
10. 自动记录可从流水删除；已有账目/草稿不受设置切换影响。更改设置取消尚未开始处理的采集；已开始的事务可完成。无障碍仍记录为notification来源，原文附“无障碍页面/支付通知+软件名”，避免改变Schema v4。

## 0.14.0：识别后弹窗与采集诊断

管理 → 自动记账：开关、目标账本和软件配置修改后立即保存；启用“识别后弹窗记账”，授予“悬浮窗权限”。微信不一定为每次付款发送通知，建议同时启用无障碍增强、授予系统权限并保持微信来源开启。需要付款成功页/账单详情提供可读取文字；此功能不通过支付软件 API 查询流水。

识别成功先持久化待确认草稿，再显示系统悬浮记账表单。可修改金额、账户、分类、日期、商户/对方和备注；点击“收起为悬浮球”后可拖动小球，再点开继续填写，当前进程中的字段保留。弹窗模式不直接自动保存。未授予悬浮窗权限、窗口显示受系统限制或队列超过20笔时，草稿仍在管理 → 待确认账单。系统终止进程后窗口及尚未保存的表单修改可能消失，已识别的草稿保留。

转账和红包不推断最终收支方向，表单要求用户选择：转给他人/消费为支出，收款/领取红包为收入，自己的账户间移动为内部转账并选择两个不同账户。只有用户确认后才生成分录；已有同日、同账户、同类型、同金额、同商户的交易会提示疑似重复，需要明确勾选“仍保存为另一笔”。忽略不会改变账户余额。保存使用后台数据库事务，重复点击及提交后进程中断重放不会生成第二笔。

修复的采集问题：支持完成付款的自然句通知（如“你向某商户付款16元”）；可信支付渠道带回复动作不再一律视为聊天；无障碍读取 text 或 contentDescription，去除相同文本，最多1000个节点；持续内容变化的去抖等待最多2秒。支持内联“当前状态：支付成功”和带明确交易字段的成功页。转账/红包成功页面可采集为待核对草稿，营销、失败和未支付等内容继续排除。

“采集与后台状态”显示来源事件计数、最近的软件、通知/无障碍、匹配/未匹配原因及后台错误代码，可刷新重试。诊断只保存元数据，不保存被过滤的聊天文字或输出财务原文日志。通知权限与服务连接分别显示，并尝试请求系统重连。再次进入系统权限设置而配置未变化时，不取消已排队的采集。

仍需在实际手机验证微信通知/页面模板、厂商后台限制和悬浮窗键盘、拖动、收起/展开。没有连接手机时不能声称真机稳定性已验证。


## 0.14.1：可查看和导出的诊断日志

入口：管理 → 智能记账 → 日志记录。默认记录，可在日志页面独立关闭、开启或清空；查看页面每3秒刷新，退到后台停止刷新。按通知/无障碍或“微信及后台”筛选；右上角菜单复制完整日志或通过系统文件选择器导出TXT。筛选只影响显示，复制和导出包含全部保留的诊断。自动记账设置页不再放置日志入口。

排查时先清空日志，返回微信进行一次实际支付或查看失败的账单详情，再回到日志页复制或导出，提供给开发者。请保留付款成功页片刻，便于系统发送无障碍事件。应用不会远程读取手机日志或自动上传日志。

日志记录系统权限与服务连接、总开关/微信来源/增强开关、电池优化状态，以及事件收到、聊天过滤、成功状态/金额/账单字段缺失、采集排队、后台启动/解析/入账/待确认、悬浮窗权限/显示/收起、表单提交结果。12位匿名采集编号可关联同一次处理。没有“收到来源事件”时优先检查服务连接和手机后台限制；收到事件但被过滤时查看原因；采集已排队但没有后台结果时检查后台错误；已有草稿但未弹窗时检查悬浮权限及系统窗口限制。

诊断私有存储保留最近48小时最多400条，相邻重复阶段合并计数，不含金额、商户、支付原文、卡号、聊天文字、异常详情或账户/账本ID。字段使用固定枚举和允许列表，显示与导出再次过滤；关闭记录保留旧日志，清空仅删除日志，不删除交易或草稿。诊断写入失败不阻止交易处理。

本版不改变支付采集规则或账本Schema，仍需在用户手机重现失败场景后依据日志判断具体原因。

## 0.14.2：微信聊天转账卡片

0.14.1真机日志显示：无障碍服务已连接并收到微信事件，但根窗口每次只暴露1–2个节点，因而连续记录 `money_missing`，没有入队。通知权限已授予，但通知服务并未实际连接。

本版额外读取 `AccessibilityEvent` 自带的文本、描述及事件源卡片子树，并在根窗口瞬时切换或不可用时保留已读取的卡片文本。仅“金额 + 你发起了一笔转账/对方已收款 + 微信转账”这类强语义卡片可在没有“支付成功”字样时进入待核对草稿。缺金额、普通聊天和已退回转账仍拒绝；转账始终要求用户选择支出、收入或自己账户间转账，不直接自动入账。

设置页对“通知已授权但服务未连接”明确提示到系统设置关闭后重新开启通知读取权限。该操作必须由用户在Android系统界面完成。

## 0.14.3：单帧截图OCR兜底

0.14.2真机日志证明微信事件文本和根节点都没有金额，因此继续扩充文字规则无法获取卡片像素。

新增“微信转账截图OCR兜底”独立开关，默认关闭。用户明确开启且已安装任一飞桨OCR档位后，微信连续两次缺少金额才截取当前屏幕的一帧，15秒内最多一次。截图仅在内存中运行本地PP-OCR，随后立即释放；不写入文件、不持续录屏、不上传。

只有OCR同时找到近期聊天时间、金额、“你发起了一笔转账/对方已收款”和“微信转账”才入队。入队文本只保留交易字段，不保留其他聊天OCR结果。转账仍只进入待核对悬浮表单，不自动入账。

该能力使用Android 11及以上的无障碍单帧截图API；开启后需在系统设置关闭并重新开启知账无障碍服务。安全窗口、厂商系统限制或未下载模型时不执行。

## 0.17.0：跨事件支付会话与页面路由

根据用户真机日志和对参考APK的REA静态分析，确认可靠实现并不是对每次无障碍回调立即套同一条正则，而是先按软件包和Activity页面族路由，再用短生命周期状态合并连续事件。静态分析只能证明参考APK包含这些路由、状态和限流结构，不证明其所有运行时分支；知账据此独立实现了自己的保守采集流程，没有复制交互动作，也没有增加自动点击或手势能力。

新流程保留同一支付页12秒内的有限文字，合并窗口事件、事件源节点和根节点；金额、成功状态、商户、账户等字段即使分批出现也能组成一份候选。第一次页面读取约160ms，部分字段缺失时在2.2秒内快速重读，避免旧版每次事件都重新延迟而导致弹窗出现过慢。已匹配立即入队；节点持续不完整才截取一帧并调用用户自行下载的飞桨OCR模型。

微信单独识别转账、红包、群收款、账单详情、小程序支付、扫码等页面族；普通聊天仍不会因为出现单个金额就形成账单。其他来源按支付、收银台、订单、账单和结果页类名及明确交易锚点进入会话。来源扩展至23个包名，但每个来源仍必须由用户在设置中开启，且实际UI/通知模板需要真机逐个验证。

通知、节点和OCR可能同时报告一笔交易。现在优先使用交易/订单号建立稳定语义标识；没有编号时使用标准化绝对金额、商户/收款方和本次页面会话。相同语义在4秒内只入队一次，新的页面会话或微信新卡片视为新交易。诊断新增“开始合并页面”“等待分段字段”“跨事件匹配”“转入OCR”四个固定阶段，仍不记录金额、商户、原文或聊天内容。

## 0.18.1：支付宝转账状态与事件降噪

支付宝失败、退款及退回判断改为匹配明确的状态行，不再因为页面说明中出现“原路退回”“退款说明”“立减优惠”等文字而丢弃已经成功的转账。新增“资金待入账、转入成功、转出成功”等支付宝转账完成状态；真正的“转账已退回、退款成功、交易失败”等状态仍会排除。无障碍页在成功采集后短暂抑制同一应用的重复事件，减少同一账单反复解析和诊断日志刷屏。

## 0.19.0：REA 某记账软件行为对照

依据 `docs/REA_YIMU_AUTOMATION.md` 的静态证据，将自动记账收紧为“包名适配器 + Activity/字段状态机”：普通首页事件不扫描，离开支付流程即丢弃未完成片段，OCR 期间不创建第二会话，成功后短时抑制事件风暴。补充支付宝/微信转账、充值、提现、到账金额和时间角色，使原生候选判定与 Dart 草稿解析保持一致。退款、还款、借贷和账户间转账仍须人工确认。

## 0.20.1：连续转账与后台快捷 OCR

无订单号的微信交易不再用“应用＋金额＋对象”作为永久采集编号。新的支付窗口会话会解除旧页面抑制；微信同一聊天窗口中新追加的转账卡片使用卡片数量和最近时间区分，因此连续给同一对象转相同金额也能生成新的待确认草稿。

通知栏“OCR截图记账”和系统快捷磁贴统一复用已连接无障碍服务的单帧截图能力，再调用设备上已下载的飞桨模型，并把OCR文字交给后台数据库处理。该入口不启动主界面或OCR模型页，也不会请求 MediaProjection 或依据缺少可信来源置信度的截图静默自动保存。只有同时存在交易金额及完成状态或账单结构字段时才显示悬浮核对表单；普通应用页面、模型缺失、空图或识别失败只在当前屏幕短暂提示。已有同日、同商户、同金额候选时，表单打开即显示“疑似重复”，用户明确勾选后仍可保存为另一笔。

REA静态观察显示，参考APK会先按来源包名分派到独立处理器；支付宝、京东/京东金融、美团/点评、淘宝/闲鱼/1688、拼多多、抖音系、快手系、饿了么、盒马、云闪付、华为钱包和建行生活各自维护页面类与状态词。知账据此改为按包隔离的页面路由，支持这些应用实际出现的收银台、支付结果和账单详情页面族。

知账的实现选择不是复制参考代码：页面类只负责启动短会话，最终仍必须同时通过来源白名单、完成状态、人民币金额和交易字段校验；不会自动点击、输入或执行手势。`购买成功`、`拼单成功`、`免密支付成功`等状态只在对应软件中有效，不会跨应用误触发。微信与支付宝红包分别要求来源包名和明确红包结构，普通支付宝账单里出现“红包优惠”不会再判成微信红包。

## 0.20.2：快捷截图生命周期修复

通知栏和快捷磁贴优先使用已授权无障碍服务的 Android 单帧截图 API，不启动 MediaProjection，不持续录屏，也不在每次截图时显示系统录屏授权框。Android 14–16 不允许永久保存 MediaProjection 的一次性授权，因此无障碍单帧截图是免重复确认的实现路径；无障碍服务未实际连接时只提示重新连接，不回退弹出录屏授权。

同时修复 Android 16 销毁透明授权页时提前停止旧截图服务的竞态。应用内主动截图仍可走系统授权；授权后透明页立即退出，原支付页面恢复到前台，截图、飞桨 OCR 和草稿生成均由独立前台服务完成。

快捷 OCR 的一次性成功、失败及缺少权限提示均显示在当前屏幕，不再为此新增状态栏通知。用户明确配置的常驻快捷入口继续保留。自动记账设置页会集中列出缺少的通知读取、无障碍、悬浮窗、通知显示权限或 OCR 模型。诊断日志保留截图请求、取得图片、读取文字及取图失败阶段，可区分系统截图失败、模型失败和后续草稿处理失败，同时仍不记录图片与交易原文。

流水删除后的“撤销”操作只显示五秒。即使开启了 Android 无障碍导航（系统默认可能让带操作按钮的 Snackbar 无限停留），知账也会用独立计时器主动关闭；五秒内仍可恢复，超时后可到回收站恢复。

## 0.21.0：优惠、商户兜底、查重与交易级日志

本版按钱迹 4.5.3 的“实付独立、优惠独立、日志按交易聚合”思路改造，同时保留知账免费、本地优先、无会员墙的产品约束。

- 优惠写入 `transactions.discount_minor`（schema v17），实付金额仍是唯一入账金额；流水和首页显示“优惠 ¥x”，手动记账和 OCR 草稿可回填。旧备份导入自动补空列。
- `PaymentDiscountParser` 支持 `已优惠/共优惠/优惠金额/优惠/立减/随机立减/碰一下支付立减/支付立减/满 X 减 Y`，并用“订单金额 - 实付”兜底；`8.5折`、无金额“优惠券”不会误识别。
- 商户字段缺失时，从页面文字和“向……付款/支付/消费”句式提取，清理金额尾缀和标点；明确的支付成功句式可直接自动入账。
- 自动入账前按“订单号 → 语义指纹 → 同日同商户同金额 → 5 分钟内金额/账户/方向”查重。商户缺失或一方只是简称（如“瑞幸”与“瑞幸咖啡”）时只阻断自动入账并保留待确认，不静默合并或丢弃；疑似重复警告会写明命中依据。
- 日志默认显示“自动记账记录”，按采集 `ref` 聚合成一笔交易，展示结果、识别摘要、原因和下一步；技术事件收进展开项或“技术日志”切换。导出时先输出交易级记录，再附技术日志和应用日志。
- 新增诊断事件 `worker_duplicate_order/semantic/same_day/time`，用于区分重复依据。原生悬浮确认会回传草稿优惠，避免确认后丢失。

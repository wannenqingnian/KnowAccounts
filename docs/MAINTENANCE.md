# 分类与账户维护（0.11.0）

## 使用入口

管理 → 分类管理：选择支出/收入；一级分类点击进入二级分类。当前层级右上角新增，右侧菜单改名/归档，拖动手柄调整同级顺序。切换“显示已归档分类”可恢复。

账户 → 归档账户：确认后从活动账户列表移出。在“已归档账户”中恢复。默认账户与自建账户使用同样规则。

## 数据规则

- 使用现有Schema v4的`sort_order`与`archived_at`，不改ID、不删除账户或分类、不重建历史分录。
- 分类名称1～40字；同收支类型、同级父分类下不能重名，含归档分类。同名归档项目请恢复或改名后再新增。
- 新增只允许同账本、同收支类型、未归档的一级分类作为上级，最多两级。分类收支类型/上级不能修改，避免改变历史统计口径。
- 排序只接受当前同级完整ID列表，拒绝重复、遗漏、其他账本、混合层级及过期列表；事务内写入。新分类追加到同级末尾。旧数据库排序并列时按原rowid稳定排序。
- 一级分类归档时，同一事务归档其全部可用二级分类；恢复一级分类不会自动恢复子项，子项可按需分别恢复，且要求上级先恢复。
- 至少保留一个可用账户及每种已有收支类型的一个可用分类，防止新记账没有可选项。
- 活动选项用于新交易和解析；账户净余额、资产趋势及分类历史统计使用包含归档项目的完整列表。因此归档不会使资产、欠款或已发生消费从统计中消失。
- 编辑涉及归档选项的旧流水时，保留金额/商户等内容，提示恢复项目或明确选择新的可用选项；不静默换账户、不将过期ID送入下拉框。删除/恢复历史流水仍按原分录计算余额。
- 归档账户的期初余额、卡号安全存储引用、还款日期不变；需要新记账或还款时先恢复。
- 加密备份包含全部项目的归档标记与顺序，完整卡号仍按既有安全存储/密码备份流程处理。恢复检查不允许活动二级分类挂在已归档上级下。

## 验证

六项数据库/备份测试覆盖分类改名后流水和金额不变、层级归档/恢复、排序与错误列表回滚、账户余额/银行卡存储保留、账本隔离与最后可用项保护、加密备份恢复。

两项界面测试覆盖默认分类菜单改名/归档/恢复，以及历史归档字段编辑不会触发下拉框断言、归档账户恢复。完整回归与Release包校验见[Android构建说明](ANDROID_BUILD.md)。仍需在实际手机检查拖动手势、系统升级和安装表现。

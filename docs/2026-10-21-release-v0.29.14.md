# 知账 0.29.14 发布说明

## 金额规则

只按实付金额入账。例：实付 38.50 元、优惠 3.50 元，余额与支出均变化 38.50 元，不是 35 元。优惠独立保存到 `transactions.discount_minor`，数据库版本为 17。

按用户确认保留手动表单“优惠不能大于实付金额”的限制。优惠不用于推导第二次扣款或零元账单。

## 本次范围

- `PaymentDiscountParser`：优惠标签、立减、满减与订单金额差额兜底；不识别“8.5折”或无金额优惠券为优惠金额。
- 手动编辑、OCR、批量确认、后台与悬浮确认透传优惠；流水及首页展示。
- OCR 优先明确商户字段，再使用页面文字与付款句式，清理金额尾缀。
- 自动入账按订单号、语义指纹、同日同商户、短时兼容商户依次查重；兜底只阻止自动入账，保留草稿供用户确认。
- 原生悬浮确认仍执行显式查重，真实第二笔需用户明确确认后保存。
- 自动记账记录按 `ref` 聚合，显示结果、原因、下一步和质量；可切换技术日志。没有 `ref` 的采集阶段仍在技术日志中查看。
- 导出按交易级记录、原生技术日志、Flutter 应用日志排列，继续遵守敏感信息开关。

## 验证与复现

发布流水线执行静态分析，并分进程运行以下回归：

```bash
flutter analyze --no-pub
flutter test test/payment_automation_test.dart
flutter test test/payment_confirmation_test.dart
flutter test test/payment_worker_test.dart
flutter test test/payment_quality_test.dart
flutter test test/discount_migration_test.dart
flutter test test/backup_test.dart
flutter test test/advanced_finance_test.dart
flutter test test/transaction_identity_test.dart
flutter test test/automation_diagnostics_test.dart
```

`discount_migration_test.dart` 验证 v16 数据库升级、旧备份补空优惠、新备份保留优惠，以及余额和消费统计不重复减优惠。识别与后台测试覆盖草稿留存、重复采集和确认保存。

本机 Windows 的部分批量测试曾出现 `did not complete`，不作为通过依据；最终发布须以 GitHub Actions 的完整检查、ARM64 APK 构建与组件校验成功为准。

## 发布与限制

- 版本 `0.29.14+80`，正式发布标签 `v0.29.14`，沿用现有固定签名与 Android ARM64 发布流程。
- 不包含工作区中的币种扩展、连续“保存并再记”以及竞品预览素材等无关改动；这些内容保留在本地。
- 尚未进行真实支付页面、真机升级覆盖安装和 iOS 验证。升级前先导出加密备份，不建议旧版覆盖已升级至 v17 的数据库。
- 金额、商户等信息仅按既有敏感日志开关保存；分享日志前检查隐私。

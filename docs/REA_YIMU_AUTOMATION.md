## 知账对照与本次补齐

知账已经具备用户选择的包名白名单、按应用页面路由、跨事件短会话、节点上限、本地截图 OCR、
去重队列和可收起悬浮表单。与上述静态行为相比，本次补齐四处差异：

1. 只有进入已知支付 Activity 或出现明确金融字段时才安排页面扫描，普通首页事件不再触发全文读取。
2. 从支付页返回登录页、首页、聊天页或无关页时清空未完成片段，避免旧状态与新页面拼接。
3. OCR 执行期间暂停新的页面会话；成功后对同一来源短时抑制，减少事件风暴和重复悬浮窗。
4. 支付宝/微信的转账、充值、提现、到账金额与对应时间、账户字段使用独立角色解析，原生匹配层与
   Dart 草稿层共享同一组完成状态，避免“已经匹配但金额为空”。

保留的知账差异是安全策略：退款、还款、借贷和账户间转账不会静默计为普通收支；有歧义时仍进入
核对悬浮窗。这些行为是为了防止重复记账，不属于静态证据能够证明的一木运行时等价项。

## 6.1.6 快捷入口与 OCR 补充复核

2026-10-10 再次以本地 JADX/REA 静态流程核对安装包：

- `com.wangc.bill.service.QuickSettingService.onClick()` 会根据用户设置在悬浮窗
  `com.wangc.bill.popup.y0`、`AddBillActivity`、透明快速页 `TransparentActivity`、模块页和语音页之间
  分流；具备悬浮窗权限时可直接调用悬浮入口，并不要求先打开主界面。
- `TransparentActivity` 是完整的轻量记账表单，包含金额、账户、分类、日期、标签和保存动作；这说明
  快捷入口的关键是“就地核对”，而不是把用户送回应用首页。
- 资源 `use_info` 明确说明“一木”的“账单导入”使用通用 OCR，并提示 Android 分辨率、字体和界面差异
  会影响准确率。静态证据没有证明其通知栏 OCR 能完全后台处理，因此知账不宣称复制这一点。

知账 0.20.1 据此采用独立实现：通知栏和快捷磁贴完成一次系统截图授权后，由前台截图服务继续在后台
运行本地飞桨 OCR，识别结果直接进入后台草稿处理器并显示悬浮核对窗；不再启动 `MainActivity` 或
OCR 模型页面。模型缺失、图片无文字或识别失败时只发送失败通知，由用户自行决定是否进入应用。

## 0.21.11 全适配器字段补齐

本轮继续沿着 `AutoAccessibilityService` 的包名分派逐个检查适配器，形成原生页面守卫与 Dart
草稿解析器共用的“来源专属字段词表”。当前覆盖一木 6.1.6 静态分派中可确认的全部应用族：

| 应用族 | 包名/变体 | 深入解析字段 |
| --- | --- | --- |
| 微信 | `com.tencent.mm` | 付款/收款/红包/群收款、金额、付款方式、到账账户、交易时间 |
| 支付宝 | `com.eg.android.AlipayGphone` | 实付/订单/提现/红包金额、对方账户、收款方、付款方式、创建/支付/收款时间 |
| 京东 | 京东、京东金融 | 实付、商品名称、交易说明、收款方、支付方式、创建时间、退款状态 |
| 美团 | 美团、点评、美团外卖 | 合计/实付、支付方式、交易/创建/下单时间、商户名称 |
| 淘宝系 | 淘宝、闲鱼、1688 | 实付价/现价/订单金额、商品或公司名称、付款方式、支付成功状态 |
| 拼多多 | `com.xunmeng.pinduoduo` | 拼单/免拼状态、支付方式、支付时间、交易单号、已选商品 |

| 快手系 | 快手、快手极速版 | 实付/免密支付、门店/商家、支付与购买成功状态 |
| 本地生活 | 饿了么、盒马 | 提交订单前置金额、已选账户、支付成功金额、优先付款方式 |

实现采用两层约束：`PaymentPageSession`/`PaymentCaptureGuard` 只允许当前包名自己的 Activity、完成状态
和字段组合进入队列；`payment_source_profiles.dart` 再把该来源的标签、同行金额及相邻节点规范化为
金额、商户、账户、时间等统一字段。别名按长度优先匹配，避免“商户名”抢先截断“商户名称”；来源
专属完成状态也不会跨应用误用。页面首页、登录页、聊天页和浏览页仍会重置或拒绝会话。

一木 6.1.6 的静态包名分派中没有滴滴分支。知账保留已有的滴滴兼容解析，但不把它表述成对一木的
复刻。测试覆盖上述 21 个一木来源包名以及知账保留的滴滴、微信双开来源，共 23 个来源配置，并校验
各来源金额、商户、日期规范化、完成状态隔离、页面路由及字段组合。

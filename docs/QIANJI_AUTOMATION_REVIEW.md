# 钱迹 4.5.3 学习资料对照与知账改进

本次输入是静态分析报告和独立教学示例，不是钱迹源码。分析过程只阅读 Markdown、Kotlin 和说明文本，没有执行附带 JAR，也没有把教学代码直接复制进产品。

## 已吸收的优点

- 页面场景识别与字段提取分层：Android 仅负责应用、窗口、完成状态与页面会话；Dart 按来源配置字段词汇并生成统一草稿。
- 多层去重：短时页面事件、跨通知/无障碍/OCR 语义指纹、数据库疑似重复分别处理；数据库命中只标记重复，由用户决定是否继续。
- 账户策略链：账户名称、信用账户、银行与卡尾号、单独卡尾号、银行名称和支付场景按可靠度选择；最高分并列时不自动选账户。
- 草稿与正式账单分离：字段不全、转账、红包、退款和重复候选均进入确认流程，正式保存仍走统一账户、预算和统计逻辑。

## 本次实际修正

1. 原生语义指纹不再抓取页面第一个金额。金额按“退款金额 / 实付 / 支付 / 转账 / 交易 / 合计”字段优先级提取；同优先级冲突时不做短时语义去重，防止漏掉真实账单。
2. 指纹加入消费、收入、转账、退款场景。相同商户和金额的付款与退款不会互相覆盖。
3. 已完成退款页可以进入待确认流程；“退款中”等未完成状态仍被过滤。退款继续由 Dart 关联原消费，不会当普通收入自动保存。
4. 账户匹配独立为可测试策略链，并把匹配原因写入证据。弱匹配或并列候选必须人工选择。

## 没有照搬的部分

- 不使用对外导出的账单广播接收器；知账继续通过应用内通道和受控后台队列交接。
- 不把固定 15 秒指纹当成账单唯一性；订单号、页面发生次序、交易时间和数据库候选各自承担不同职责。
- 不因支付软件名称直接假设扣款账户；只识别到“银行卡”或出现多个同尾号账户时不会自动保存。
- 不把完整页面、截图或账户原文发送到远程 AI；OCR 和规则解析保持本地，持久化前对长编号脱敏。
- 不执行教学包中的 JAR，也不把示例的全局正则和“下一个文本节点”当成生产页面模板。

## 验证重点

- 页面同时含原价、优惠、余额和实付时，指纹只使用实付。
- 部分退款时使用退款金额，不使用原订单金额。
- 两笔同金额同商户但交易时间或页面发生次序不同，均可进入账单流程。
- 同银行多张卡优先使用银行和尾号；同分冲突不自动扣错账户。
- 已完成退款进入待确认，退款中、支付失败和营销页面不生成草稿。
